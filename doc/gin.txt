*gin.nvim*  Lua Git integration for Neovim

                                                            *gin-introduction*
                                                            *gin-requirements*
Requires Neovim 0.10+ and Git. No Deno or Denops runtime is required.
This rewrite is in progress. Its reference is vim-gin commit
24cce091cfa32c013bc53cf4ff8f721d6690cf24. See MIGRATION.md in the repository
for implemented behavior, validation evidence, and remaining compatibility work.

                                                                   *gin-usage*
COMMANDS                                                        *gin-commands*

                                                         *gin-commands-silent*
:Gin [++wait] [++worktree={path}] {git-arguments}                       *:Gin*
    Execute Git asynchronously and display live output. :silent suppresses the
    final success message; progress remains visible as in the pinned upstream.
    :silent! also suppresses the final error message. ++wait waits for completion
    while servicing proxy requests and displaying progress. Failures display a
    friendly message without throwing from the user command. Successful commands
    emit |GinCommandPost|. ++processor={command} transforms stdout; processor
    failure prevents the success event.

:GinBuffer [++opener={opener}] {git-arguments}                    *:GinBuffer*
    Display Git output in a buffer. :edit reloads it. ANSI Git colors become
    highlights; ++monochrome skips forced Git coloring. Supports ++worktree,
    ++filetype, ++processor, ++emojify, ++enc and ++ff.
    ++diffjump[={revision}] enables diff jumps using the revision and its first
    parent. An omitted or empty revision means HEAD. ++difffold enables folds.

:GinStatus [options] [flags] [-- pathspecs]                       *:GinStatus*
    Display status using Git's untracked-file settings. Use --untracked-files=all
    (or -uall) to list individual files inside untracked directories. << stages
    the selected lines; >> unstages them. dd opens a smart diff, pp opens patch
    panes, !! opens conflict panes, == stashes the selection, <CR> opens the
    working file, and yy yanks its absolute path.
    -uno hides untracked files; -unormal groups untracked directories. Put
    option-like paths after --, for example :GinStatus -- -uall.

:GinBranch [options] [flags] [patterns...]                       *:GinBranch*
    List branches. <CR> switches branches and yy yanks the branch name.
    The default display uses Git's color.branch.* settings.
    Color atoms in --format render as highlights; --no-color disables them.
    --abbrev={n} and --no-abbrev control the default commit column and its yank.
    --no-verbose shows names only; --no-verbose -v shows abbreviated details.
    Actions include new, move, delete, worktree, merge, rebase, and log.
    Remote deletion deletes the remote ref. Use the action help to inspect
    available variants before running destructive actions.

:GinLog [options] [flags] [revision] [-- paths...]                   *:GinLog*
    Display commit history. <CR> shows the commit; yy yanks its hash.
    Actions include cherry-pick, revert, reset, tag, fixup, merge and rebase.
    Paths are repository-relative. ++emojify renders GitHub emoji names.

:GinReflog [options] [flags] [ref]                               *:GinReflog*
    Display reflog history with the implemented GinLog actions.

:GinStash [options] [flags]                                      *:GinStash*
    List stashes. <CR> shows the stash; yy yanks its ref. apply, pop, and drop
    act on the first selected entry. apply:index and pop:index restore the
    index as well. Supports ++emojify.

:GinTag [options] [flags] [patterns...]                             *:GinTag*
    List tags. <CR> shows the tag; yy yanks its name. Actions include delete,
    switch:detach, and yank:commit. Supports ++emojify.
    Color is disabled by default; --color=always enables color atoms in --format.

:GinEdit [options] [commitish] {path}                              *:GinEdit*
    Open the index version by default, or an immutable revision if commitish
    is supplied. Paths are repository-relative. :write on an index buffer
    updates the index while preserving the working file. Supports ++worktree,
    ++opener, ++enc and ++ff.

                                                    *<Plug>(gin-diffjump-new)*
                                                    *<Plug>(gin-diffjump-old)*
                                                  *<Plug>(gin-diffjump-smart)*
:GinDiff [options] [flags] [commitish] [-- paths...]               *:GinDiff*
    Display a comparison; --cached compares the index. Revision ranges are
    supported. Paths are repository-relative. <CR> jumps to the matching side
    of a changed line, g<CR> to the old side, and <C-g><CR> to the new side.
    zc/zo close/open file folds. Supports ++worktree, ++opener, ++processor,
    ++enc and ++ff.

                                                         *<Plug>(gin-diffget)*
                                                       *<Plug>(gin-diffget-l)*
                                                       *<Plug>(gin-diffget-r)*
                                                         *<Plug>(gin-diffput)*
:GinPatch [++no-head] [++no-worktree] [path]                      *:GinPatch*
    Open HEAD, index and working-file diff panes, focusing the index. Path is
    relative to cwd and defaults to the current file. In the index pane, dol
    gets a HEAD hunk, dor gets a working-file hunk, and :write saves the index.
    do gets the right pane if present, otherwise the left. dp puts the hunk
    into the working pane. Other panes use do/dp with the index where possible.
    Visual mappings pass the selected line range to Neovim's diffget/diffput.
    Diff boundaries determine which additions/deletions belong to that range;
    this is not an arbitrary line replacement operation.

:GinChaperon [++no-ours] [++no-theirs] [path]                  *:GinChaperon*
    Open theirs, working-file and ours conflict panes, focusing the working
    file. Path is relative to cwd and defaults to the current file. Conflict
    blocks are removed from the buffer. dol/dor get hunks from theirs/ours;
    do prefers ours. Side panes use dp to put hunks into the working file.
    Write the resolved file, then stage it explicitly.

:[range]GinBrowse [flags] [revision] [path]                     *:GinBrowse*
    Open a hosting URL, defaulting to the current file. --no-browser prints
    it; ++yank=a copies it to register a. Supports --home, --commit,
    --permalink, --remote={name}, ++repository and ++worktree. GitHub, GitLab
    and Bitbucket routes are supported. --pr finds GitHub pull requests and
    GitLab merge requests from commit messages and local merge ancestry, using
    remote HEAD or main as fallback.
    A path may end with :line or :start:end to select lines. An explicit
    two-number suffix preserves both endpoints, even when equal.
    Use -- before literal paths beginning with - or ++, for example:
        :GinBrowse --no-browser HEAD -- -notes.md

:GinBlame [options] [commitish] {path}                           *:GinBlame*
    Open synchronized attribution, committed content and commit details.
    <CR> follows the line's source commit and historical filename; selecting
    that commit again visits its parent. <C-O>/<C-I> traverse visited revisions.
    Source and attribution windows use winfixbuf to prevent accidental buffer
    replacement. Reloading source or attribution refreshes the panes.
    Closing a pane closes its companions. Supports ++worktree, ++opener,
    ++enc, ++ff and ++emojify.
    Emoji rendering affects commit summaries in attribution and details,
    preserving authors, message bodies and literal source text.

:GinCd                                                            *:GinCd*
:GinLcd                                                          *:GinLcd*
:GinTcd                                                          *:GinTcd*
    Change global, window-local or tab-local cwd to the buffer's repository.

ARGUMENTS                                                       *gin-arguments*

                                                                *gin-worktree*
Commands locate the repository from the current buffer, then cwd.
++worktree={path} explicitly selects a repository where supported.
Use Vim command argument syntax: escape spaces with backslashes. %:p expands
the current filename. The -- separator ends ordinary ++option parsing. :Gin
handles bare ++wait tokens separately: every occurrence is removed, even after
--, and enables waiting. Use ./++wait to pass a file with that name to Git.
Filename expansion still applies after --.
Example: >
    :GinStatus
    :GinEdit HEAD src/main.lua
    :GinDiff --cached -- src/main.lua
    :GinBuffer ++opener=split log --oneline -10
<
                                                               *gin-functions*
require('gin.util').reload([bufnr])                           *gin-util-reload*
gin#util#reload([bufnr])                                     *gin#util#reload()*
    Schedule :edit for the specified buffer (default or 0: current buffer).
    A buffer hidden in the current tab reloads once on its next BufEnter.
    Reloading another visible buffer restores the original window afterward.
    Displaying windows retain their cursor and scroll positions where possible.
    Unsaved changes are retained and :edit failures are reported with
    vim.notify(). Requests for buffers wiped before execution are ignored.
    Listing views use this deferred reload after GinCommandPost; GinStatus also
    uses it after file writes. Hidden views refresh on their next entry.

                                                           *gin-commands-file*
require('gin.util').expand(expr)                              *gin-util-expand*
gin#util#expand(expr)                                       *gin#util#expand()*
    Expand a Vim filename expression. For GinEdit, GinDiff and file-filtered
    GinLog buffers, return the first represented file's absolute path. Views
    without a file path and unrecognized URI data retain their expanded name.
    Commands use the same function for % and # arguments.

require('gin.util').worktree([path])                        *gin-util-worktree*
gin#util#worktree([path])                                 *gin#util#worktree()*
    Return the repository worktree for an explicit path, or use the current
    buffer and window directory when omitted. Raise an error if no repository
    can be found. An invalid explicit path does not fall back to the current
    repository.

The Vimscript utility functions delegate to the Lua implementations above.

                                                            *gin-buffer-names*
Gin buffer names identify a repository, view options and command-specific data.
Match their scheme in autocmds; use |gin#util#expand()| to obtain a represented
file path. Prefer names obtained from existing buffers over hand-built names.

New Lua buffers use this layout (query and fragment are optional): >
    {scheme}://{worktree}?{parameters}#{fragment}$
<
The worktree is absolute. Parameter keys/values and fragments are percent-encoded;
parameters are key=value pairs joined by &. The final $ terminates the encoded
fragment and is not part of its decoded content.

The readers also accept pinned upstream names with a semicolon before their
parameter portion. Their fragments differ by view, as described below. These
are descriptions of upstream compatibility data, not templates for new Lua
names. In particular, Lua log/reflog/stash fragments contain JSON argument
arrays, whereas upstream stores flags and revision selectors in parameters.

                                                         *gin-buffer-name-gin*
gin://     |:GinBuffer|
    The upstream fragment contains space-joined Git arguments followed by $.
    Parameters include processor, monochrome, emojify, diffjump, difffold and
    filetype. Lua-generated fragments escape whitespace and backslashes within
    arguments before URI encoding.

                                                   *gin-buffer-name-ginbranch*
ginbranch://     |:GinBranch|
    Upstream parameters contain branch flags; its fragment contains space-joined
    branch patterns followed by $. The filters are retained on reload and used
    when selecting action targets.

                                                     *gin-buffer-name-gindiff*
gindiff://     |:GinDiff|
    Upstream parameters contain diff flags, commitish and processor. Its
    fragment is a JSON array of paths relative to the worktree. Cached diffs
    retain their index-side jump targets when opened from these names.

                                                     *gin-buffer-name-ginedit*
ginedit://     |:GinEdit|
    The fragment identifies a repository-relative file. A commitish parameter
    selects a revision; absent or empty commitish selects the index. For example:
>
    ginedit:///path/to/repo;commitish=HEAD#file.lua
<
    Index buffers support write-back while preserving the working file. GinPatch
    uses an index buffer for its INDEX pane; WORKTREE is an ordinary file buffer.

                                                      *gin-buffer-name-ginlog*
ginlog://     |:GinLog|
    Upstream parameters contain log flags, commitish and emojify. Its fragment
    is a JSON array of repository-relative paths. Reloads retain this selection.

                                                   *gin-buffer-name-ginreflog*
ginreflog://     |:GinReflog|
    Upstream parameters contain reflog flags, ref and emojify. A fragment is not
    needed for upstream names. The ref selects the reflog being displayed.

                                                    *gin-buffer-name-ginstash*
ginstash://     |:GinStash|
    Upstream parameters contain stash-list flags and emojify, with no fragment
    needed. Filters are restored when opening and reloading the view.

                                                   *gin-buffer-name-ginstatus*
ginstatus://     |:GinStatus|
    Upstream parameters contain status flags, including the default
    untracked-files flag. Its fragment contains a JSON pathspec array followed
    by $; the terminator is outside the JSON. Staging and automatic reload
    preserve these filters.

                                                      *gin-buffer-name-gintag*
gintag://     |:GinTag|
    Upstream parameters contain tag flags and emojify. Its fragment contains
    space-joined tag patterns followed by $. Display flags and patterns survive
    reads and action selection.

                                                    *gin-buffer-name-ginblame*
ginblame://, ginblamenav://, ginblamedetail://     |:GinBlame|
    These identify the file-content, navigation and internal commit-detail
    buffers respectively. Upstream parameters include commitish and emojify;
    the fragment identifies the repository-relative file. The panes share the
    selected file and revision.

                                                        *gin-commands-options*
Supported openers are edit, split, vsplit, tabedit and pedit. Availability and
pane layout depend on the command. ++enc/++encoding and ++ff/++fileformat select
decoding on commands that support them. ++processor accepts a command with its
arguments escaped as one Gin argument.
For output views, GinEdit and either Blame pane, :edit ++enc={encoding}
++ff={format} overrides the URI decoding settings for that read. Ordinary
reload uses the URI defaults.

Read encodings use the pinned upstream's TextDecoder labels. Explicit encoding
selection replaces malformed byte sequences with U+FFFD and rejects unknown
labels. For example, latin1 and ascii select Windows-1252, and utf-16 and ucs-2
select UTF-16LE; use utf-16be for big-endian input. Native-only names such as
ucs-2le, ucs-4, utf-32, cp932 and cp936 are not accepted as read labels. Use sjis
or gbk for the corresponding legacy Japanese or Chinese input.

Without an explicit encoding, buffer reads try 'fileencodings' in order using
strict decoding. Invalid or unsupported candidates are skipped. If none works,
the bytes are decoded as UTF-8 with replacement and 'fileencoding' is empty.
The ordinary :Gin command defaults to UTF-8 instead of using 'fileencodings'.
The raw Git output is preserved; decoding affects its display. These read rules
do not define which encodings the index writer accepts.

:read {URI} inserts output for gin://, ginedit://, gindiff://, gintag://,
ginlog://, ginreflog:// and ginstash:// buffers. Obtain the URI from an existing
Gin buffer's name. Reads support line addresses and decoding without changing
the destination buffer's encoding or fileformat. URI compatibility is still
being audited; avoid constructing URIs by hand.

                                                                  *gin-action*
ACTIONS                                                           *gin-actions*

In status, branch, tag, log, reflog and stash views:
    a       Choose an action, with completion.
    .       Repeat the chosen action on the current selection.
    ?       Show action help.

                                                   *<Plug>(gin-action-choice)*
                                                     *<Plug>(gin-action-echo)*
                                                     *<Plug>(gin-action-help)*
                                                 *<Plug>(gin-action-help:all)*
                                                   *<Plug>(gin-action-repeat)*
                                                          *gin-action-mapping*
                                                                *gin-mappings*
Actions use <Plug>(gin-action-{name}) mappings. Available actions depend on the
view. help:all lists detailed variants. echo prints selected candidate metadata
as JSON. Normal mode selects the current line; visual mode selects a range.
User-defined global and buffer-local action mappings appear in discovery.

Lua callers can use: >lua
    local action = require('gin.action')
    local buf = vim.api.nvim_get_current_buf()
    action.list(buf)                   -- sorted action names
    action.call(buf, 'echo', { 1, 2 }) -- inclusive, one-based line range
<
In an initialized Gin action view, use action.define(buf, name, callback).
The callback receives (buf, range). action.range() returns a copy of the current action selection.
Treat other module internals as subject to change during the migration.

EDITOR AND PROMPTS                                                 *gin-proxy*

Plugin startup exports GIT_EDITOR and GIT_ASKPASS for terminal jobs as well as
Gin commands. Set the disable flags below before loading the plugin to preserve
the corresponding inherited environment variables.

Gin commands open Git editor requests in a new tab. Buffer-local
:Apply writes the file and continues Git; :Cancel rejects the request. Quitting
asks whether to apply. Git credential prompts use masked Neovim input.

                                                   *g:gin_proxy_editor_opener*
    g:gin_proxy_editor_opener            Choose another supported opener.
                                                  *g:gin_proxy_disable_editor*
    g:gin_proxy_disable_editor           Set to 1 to retain Git's editor.
                                                 *g:gin_proxy_disable_askpass*
    g:gin_proxy_disable_askpass          Set to 1 to retain Git's askpass.
                                           *g:gin_proxy_apply_without_confirm*
    g:gin_proxy_apply_without_confirm    Set to 1 to apply on quit directly.

The gin_proxy_disable_editor and gin_proxy_disable_askpass flags accept booleans
or numbers. Unset, v:null, false and zero keep the corresponding proxy enabled;
strings, lists and dictionaries are rejected before starting Git.

With filetype plugins enabled, gitcommit/gitrebase buffers get :Accept (:wq)
and :Cancel (:cq) aliases unless already defined. Disable them with
                               *g:gin_proxy_disable_accept_and_cancel_aliases*
g:gin_proxy_disable_accept_and_cancel_aliases = 1. Proxy buffers retain their
request-specific :Apply and :Cancel. ++wait services proxy requests and keyboard
input during editor requests.

PROGRESS INDICATOR                                             *gin-indicator*

gin#indicator#echo#open(id)                       *gin#indicator#echo#open()*
gin#indicator#echo#write(id, lines)              *gin#indicator#echo#write()*
gin#indicator#echo#close(id)                     *gin#indicator#echo#close()*
    Legacy echo functions delegate to require('gin.indicator.echo').
    write() displays a list of lines synchronously without adding history.
    Empty lists and writes without an open indicator are ignored. The echo
    backend shares its display settings with native Lua progress streams and
    restores them after the last user closes. IDs are accepted but unused,
    matching the pinned echo backend.

With progress enabled, require('gin.git').run(args, opts) accepts
stdout_indicator and stderr_indicator. Each is "echo", "null", or a backend
name providing gin#indicator#{name}#open/write/close. The stdout default is
"null" ("echo" with progress = "both"); stderr defaults to "echo". Backends
receive a distinct ID per channel and decoded line arrays. Captured Git output
remains unchanged. Backend failures close opened channels and raise an error.

require('gin.command').execute(opts) accepts the same indicator names alongside
fargs and smods. Both channels default to "echo"; smods.silent suppresses them
unless progress = true. The :Gin entrypoint enables progress explicitly.
Backend failures skip processors and GinCommandPost. With ++wait they raise an
error; asynchronous calls report through vim.notify unless emsg_silent is set.
An optional on_error(message, result) callback handles execution failures in
either mode instead; result is supplied for a failed Git or processor exit.
The user-command wrapper uses this callback for friendly reporting. Direct Lua
calls without the callback retain exception/notification behavior.

STATUSLINE                                                     *gin-components*

Lua functions return cached strings and update asynchronously:
    require('gin.component.branch').ascii() / .unicode()
        Branch and upstream.
    require('gin.component.traffic').ascii() / .unicode()

    require('gin.component.worktree').name() / .full()

Existing Vimscript statusline expressions can use these Lua-backed wrappers:

EVENTS                                                             *gin-events*

                                                        *GinCommandPost*
User GinCommandPost
    Successful commands schedule this event 100ms after the latest completion.
    Completions within that interval are combined into one event. ++wait waits
    for the command and processor; the event and view refresh happen afterward.
    List views and components use it to refresh. Gin retains eventignore=all
    from dispatch even if the option is restored before asynchronous completion.

                                                        *GinComponentPost*
User GinComponentPost
    Emitted when asynchronous component data is ready.

LIMITATIONS                                                   *gin-limitations*

The migration is incomplete. See MIGRATION.md for the detailed audit status.
Git processes and output processors have no implicit time limit. Gin ++wait
and synchronous buffer operations service proxy requests and progress while
waiting. Keyboard-driven commit, cancellation and repeated reword requests are
tested with asynchronous Gin and Gin ++wait, including all editor openers.
GinBuffer commit is also tested with keyboard input and :Apply. Other synchronous
buffer workflows and nested commands during an editor request remain unaudited.

The g:gin_log_parse_pattern, g:gin_reflog_parse_pattern,
g:gin_tag_parse_pattern and g:gin_stash_parse_pattern settings accept JavaScript
regular expression strings (constructed without flags). A pure Lua matcher is
included; Node, Deno and native extensions are not needed at runtime. Unset or
v:null uses the existing default parser. A custom pattern is applied directly
to nonempty displayed lines; no-match does not fall back to default candidates.

Log/reflog use capture 1 as the commit. Tags use capture 1 as the commit and
capture 2 as the tag. Stash uses capture 1 as the reference and parses capture 2
as a decimal index. Invalid patterns and missing captures required by an action
raise errors. Optional captures are empty slots when yanked. Isolated UTF-16
surrogates in selected captures cannot be converted to Neovim strings.

Regex compatibility has curated, generated and long-input test coverage, but is
not proven complete. Deep nesting, pathological backtracking and invalid input
encodings remain under audit; matching currently has no implicit time limit.
Custom indicator APIs, remaining display options, URI compatibility and legacy
Vimscript APIs also remain under audit.

STARTUP GUARDS                                                *gin-loaded-guards*

Set a loaded marker before plugin loading to skip that feature. Presence is
what matters: even v:false prevents loading. g:loaded_gin controls Gin,
GinBuffer and their public event placeholders; it does not disable the other
features. The independent markers are:
